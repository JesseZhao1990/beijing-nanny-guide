# 北京育儿嫂机构比较手册

截至 2026-09-21 的中文公开资料调查网页。现有 125 个机构、品牌或平台档案：91 项有北京育儿业务线索，30 项业务仍待确认，4 个平台入口。条目按品牌及入口组织，不等于同等数量的独立法人。

全部主表条目均已完成定向检索，包含 9 项发现、逐项来源及读取边界、检索关键词、口碑结论、仍需直接核实的问题。基础九项调查记录 636 组网页查询、401 条档案来源；来源可能跨条目重复，不当作独立样本数。

## 范围与证据

- 逐项交叉比对北京市人社局 30 家品牌企业、中国家协北京栏目 73 个单位、北京家协 36 家理事单位，共 139 条名录处理记录。各名单有重叠，也含培训、养老、医院和配套单位，不能简单求和为育儿机构数。
- 另外从机构业务页、58、京东商户、政府招聘及公开报道补充候选。范围不等于北京市全部工商在营家政门店的穷尽普查。
- 原先 56 个条目及此次扩充的候选均保留主体、北京业务、经营线索、换人、退款、费用、人员筛选、督导、联系方式九项调查。未知项明确记录检索结果和缺口。
- 55 个条目有此次小红书站内搜索或正文读取记录；其他条目不声称已经读过小红书正文。本轮补查前有 32 条小红书材料记录和 45 条其他材料，包含同源、异地、异工种及商家自述，不能视为同等数量独立育儿订单。
- 同一个帖子涉及多家机构时按品牌分别解释；日期未显示年份则不补造；单方叙述、经营者宣传和独立报道明确区分。未电话联系、未下单、未验证当期合同和候选库存。

政府优先参考分 v2.0 以正式政府推选为主要筛选依据，再比较公开服务保障资料。分数不代表服务质量、满意度或投诉率；原联系批次保存在导出资料中供回看。

## 文件

- `dist/data.json`：全部档案、来源、查询记录、口碑材料和名录筛查，可从网页下载。
- `dist/research.csv`：125 个条目的九项调查、口碑结论、关键缺口、网页查询和来源导出。
- `dist/index.html`、`dist/styles.css`、`dist/app.js`：无第三方运行依赖的响应式界面。

研究原始文件保存在任务专用 Agent Reach 报告目录，未包含浏览器登录信息或凭证。静态网站仅存面向用户的调查结果，不传送搜索输入。

六个入口：先联系谁、政府依据与评分、全部机构、口碑证据、投诉与处理、签约前核对。支持关键词、类型、北京业务状态、体验证据筛选；每家可展开完整档案和逐项评分依据。

## 政府优先比较模型 v2.0（2026-09-21）

125 个条目已逐一核对四份正式政府名单，并保留完整列名法人和品牌对应关系。政府名单未提供高低名次；网页次序是本手册自行制定的比较顺序，不是政府排名或质量认证。

- 政府记录最多60分：2025年十省区市家政劳务品牌推选中的北京30家记60；2024年度员工制历史记录记15；2023年度员工制历史记录或2025年“河北福嫂”劳务输入基地记10。取最高值，不叠加。
- 员工制认定规则有效期一年，2023/2024均已成为历史记录。2025劳务品牌和输入基地公告未载明固定有效期，仅确认当年正式入选事实。本轮未取得2025/2026员工制最终更新名单或较新企业星级结果；2026行业质量政策不当企业入选名单。
- 其余40分沿用逐家判读的公开证据：换人15、退出退款10、人员筛选5、督导售后5、费用透明度5。服务项得分=档位/5×权重，最高只使用4档，因为尚未核实本单合同、实际候选或履约。0不表示服务差。
- 主体可归属和北京育儿业务线索改为分组门槛。20家进入政府品牌推选优先组；3家其他政府记录；30家补充候选；37家主体待核；31家北京育儿业务待核；4个平台入口。首页仅展示政府品牌优先组。
- 排序先分组再比较得分；只有政府品牌优先组提供组内名次，同分并列。这是选择偏好，不能将跨组分数当连续的服务质量尺度。其他政府记录的排列不等于当期认证优先。
- 京东家政记录其政府入选事实，但因具体北京育儿服务和签约责任仍未核清，维持平台入口组。找个保姆完整法人未核清，进入主体待核组；官网条款不能使其进入优先推荐。
- 阿姨来了/嘉乐会、爱侬不同法人、正点/京嫂等仅按有来源的品牌关系关联，不将资格扩大至所有相关公司或所有订单。京嫂输入基地近名主体关系待核记录不计分。
- 投诉、司法与监管材料独立保留；不按投诉数量或未搜到投诉加减分，不计算无分母的投诉率。

`research/government/sources.json` 保存11份来源说明，其中四份是正式名单；`mapping.json`保存125条人工主体/业务映射。`scoring/rubric.json`是v2规则；`rubric-v1.json`与`reviews-*.json`保留原人工六维证据判读，旧主体档位仅是门槛的部分证据，须结合本轮名称冲突和政府主体复核。

`python3 scripts/build_scores.py`可重新生成全部参考分与CSV。`node scripts/test_scores.cjs`验证全部125条、政府法人精确匹配、过期认定、去重不叠加、主体/业务门槛与分组；`node scripts/test_complaints.cjs`验证原投诉记录保留及去重。评分与完整研究CSV均使用v2，不混用旧排名。

## 投诉与处理补查（2026-09-21）

125 个条目逐家补查黑猫、消费保、监管/消协/司法/媒体，共511次公开网页定向查询。另对123个单体/品牌条目的131组主体和别称进行12315官方站内查询；58同城商户频道与京东第三方商户频道按店铺分开，不合并为平台投诉。官方查询查看首屏，选取16条具名详情核对处理结果，未遍历全历史、所有分支或非公开调解。

- 本轮整理55条投诉、媒体、监管、司法及历史记录，其中部分是已有材料补充后续，部分不属于投诉；另补16条12315详情。不当作独立北京育儿订单数，也不依数量加减分。
- 同源材料按既有ID、投诉编号或规范链接去重，保留消费者说法、企业回应、处理结果、时间、城市、工种与读取边界。自动完成、企业单方声称退款、消费者确认、达成调解协议分别显示。
- 公开索引未命中不是零投诉证明，12315公示也不是处罚认定。原页打不开时标明仅见索引或沿用旧快照，未冒充正文核验。
- 投诉补查未按条数改变原证据档位；后续v2政府优先模型重新计算了分数。网页口碑提示与投诉专页展示新增材料，原调查摘要仍可回看。
- `research/complaints/`保存可公开的逐家核查记录、官方查询摘要、16条详情与来源；不含消费者姓名、手机号尾号或登录信息。
- `scripts/build_complaints.py`合并投诉核查数据及导出表；先运行它，再运行`python3 scripts/build_scores.py`。`dist/complaints.csv`逐家导出，评分和完整调查CSV同时附有本轮结果。
- `dist/complaints.js`提供投诉专页和机构档案中的查询记录。原有小红书资料保留，不将跨平台相似描述直接判为同一订单。
